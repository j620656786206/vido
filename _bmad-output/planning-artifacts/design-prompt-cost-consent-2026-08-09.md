## 1. 為什麼要做這個設計

2026-08-07 生產首次啟用管線時發現：按下「掃描媒體庫」會**自動**把整個媒體庫（實測 1026 筆）派進字幕生成佇列，其中約 2/3 走付費語音辨識（whisper-1 $0.006/分鐘，整庫粗估 US$200±），**全程沒有任何金額提示或確認**。

根因不是 bug，是三個各自合理的決定疊出來的盲點：M1 時代自動派工很合理（每集約 $0.03、且已處理過的檔案幾乎零成本跳過）；能力閘門（FR23）只驗「有沒有金鑰」而非「使用者是否同意花這筆錢」；M2 接上 ASR 後單集成本漲兩個數量級，但沒人回頭重審同意模型。

**Alexyu 裁定（2026-08-07）**，本設計要實現三件一體：

1. 「掃描媒體庫」只做檔案與 metadata 更新，**不再自動派字幕工**
2. 字幕生成走**獨立畫面**：列出候選、顯示每項的預測路線與成本估算、可批次勾選／剔除後確認送出
3. 批次帶**總預算上限**

### 2.2 程式碼現況（本設計要補的洞）

- **執行前沒有任何清單**：現有批次對話框的閒置態只有「缺字幕的項目 38」這種**聚合數字**，列只在批次開始後才存在
- **全站沒有任何成本「估算」**：所有金額顯示都是 SSE 回報的**實際已花費**
- **預算上限目前是環境變數**（`AI_RUN_BUDGET_USD`），使用者看不到也改不了，只在批次跑起來後才出現在 SSE 裡
- **掃描完成沒有通往字幕生成的動線**
- 生成流程目前**僅支援電影**（影集在前端被過濾掉）——清單畫面要能表達這件事，或標示影集項目為不可選並說明原因

### 2.3 三個會影響畫面誠實度的技術事實（**設計必須據實反映**）

1. **路線需要探測才知道**：只有已經被管線處理過、標記為「無文字源」的項目，我們才確定它需要語音辨識；從未探測過的項目要跑一次 ffprobe（本機、毫秒級、**免費**）才知道能不能抽內嵌字幕。→ 所以需要一個「分析中」的前置畫面。
2. **片長來自 TMDb 且可能沒有**：`runtime` 欄位是 TMDb 提供的分鐘數，可為 null（未比對的項目就沒有）。→ 估價要標示為**預估**，片長未知時要明講採用的預設值。
3. **翻譯成本無法事前精算**：取決於字幕行數，抽取前不可知。→ 估價以每分鐘均價概算，不可呈現成精確報價。

## 4. 設計原則（Sally review 時的驗收準則）

1. **金額永遠與動作同框**：任何可能花錢的按鈕，同一視野內必須看得到預估金額與上限。
2. **免費與付費在視覺上分離**：抽取路線用中性／成功色系；語音辨識用警示色系但**不得**用錯誤紅——花錢不是錯誤。強調色（accent）依 Sally 2026-07-05 裁定保留給「進行中」，此處不可佔用。
3. **預估必須自稱預估**：每個總額旁都要有「預估」字樣，且說明不確定來源（片長來自 TMDb、實際依內容長度）。
4. **預設選取＝零成本**：初始狀態預選「可抽取內嵌」的免費項目，付費項目**預設不選**——使用者必須主動選擇花錢。
   *（替代方案：預設全不選 + 顯著的「選取全部免費項目」按鈕。前者少一次點擊、後者更中立；本稿採前者，Alexyu 可推翻。）*
5. **不可逆的東西要能反悔**：確認對話框是最後一道，之後的執行畫面（F8）已有「全部取消」。

### 待補項

- **[M1] 缺「預估超出預算上限」狀態（真缺口）。** F16 示意的是 $4.50 < 上限 $5.00 的順境，但這個功能最需要處理的正是逆境：使用者選了 96 部語音辨識（預估約 $25.80）而上限 $5.00 時，依現有文案「達到上限會自動暫停」，使用者會預期 96 部全做完，實際跑到 $5 就停 —— **期待與事實不符，正是本 feature 要消滅的東西**。
- **[M2] 手機版缺批次選取工具列（跨端功能落差）。** 桌面有「全選 checkbox + 選取全部可抽取（免費）+ 清除選取」，手機版整列缺席。Alexyu 的原始要求明列「可以進行批次增加或刪減的動作」；142 部逐項點在手機上不可行。
- **[L1] 缺空狀態畫面（Sally 的提示詞疏漏，非 agent 問題）。** §3 規格漏寫「全部影片都有繁中字幕」的狀態。
- **[L2] 示意資料小瑕疵（不影響設計）：**「星際效應」是知名電影、TMDb 必有 runtime，拿它當「片長未知」示例略不自然。純假資料，可不改。

### 待裁定

- **[D1] 清單畫了影集（怪奇物語 S4E7），但手動批次後端目前僅支援電影。** sub-3-2 已讓**自動管線**支援 episode，但 generation batch endpoint 仍是 movies-only（前端過濾影集）。設計已隱含選擇「後端擴充」路線。兩個方向：
  - **(a) 後端擴充批次支援 episode** —— sub-3-2 的媒體型別感知已鋪好路，工程量不大；影集正是缺字幕大宗。**Sally 建議走這條**，但它會擴大 BE story 範圍。
  - (b) 畫面標示影集為不可選並說明原因 —— 範圍小，但把已經做好的 episode 能力關在門外。
