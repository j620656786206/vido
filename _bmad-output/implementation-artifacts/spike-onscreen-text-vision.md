## 及格線（開跑前寫定，跑完不改）

1. **抓到：4 題至少 3 題**——時間差 ±5 秒內、意思對（書名、「三年後」）。
2. **多抓：整集「不該翻卻翻了」最多 5 處**——片頭片尾名單、公司 logo、背景裡看不清或無意義的字都算錯；官方沒翻、但確實是劇情相關的字（例如紙條、招牌）另外列出，不算錯，給 Alexyu 判斷。
3. **錢：一集 ≤ US$1.00**（這集翻譯本身 US$0.35）。
4. **做得到：只用 ffmpeg＋一個 API 呼叫的方式**——正式機（Docker、沒有 GPU、沒有本機 OCR）也能跑。

## 做法

- ffmpeg 每 2 秒取一格，縮成寬 512，**3×3 拼成一張圖**（約 1,710 格 → 190 張圖）。每張圖附上 9 格各自的時間。
- 模型：預設 `claude-opus-5-5`（Anthropic 目前預設的模型；不為了省錢自行換小模型）。結構化輸出（JSON schema）：每處畫面字回報格子編號、英文原文、類型（字卡／書／招牌／紙條／名單／logo／其他）、要不要翻、繁中翻譯。
- 後處理：同一段文字連續出現的格子合併成一處；和考卷比對；用 API 回報的 token 數算錢。
- 第一輪跑下來發現 512 寬的小格看不清書名，所以加了第二步：模型若說「這格有字但看不清」（書、紙、招牌），就把那一格原尺寸截圖再看一次。
- 程式放 `scripts/onscreen-text-spike.py`（Python＋官方 `anthropic` SDK，跑在 scratchpad 的 venv）。**逐句結果不進 git**（repo 是公開的，`feedback_public_repo_no_transcripts.md`），只記數字。

### 學到的

- **方向是可行的**：會看圖的模型能分清「劇情要讀的字」和「名單、logo」，時間卡、書名都讀得出來，還會用台灣通行書名。
- **小字要放大看**：拼圖只夠找出「哪裡有字」，書名要原尺寸才讀得到。
- **錢是卡關的地方**：大部分花在掃 190 張拼圖。可以省的地方（都沒試）：取樣改 3 秒一格（約省 1/3）、跳過片頭片尾名單（省得不多）、換較便宜的模型（Sonnet 5.5 價格是一半、Haiku 4.5 是四分之一，但辨識品質要另外測）。**換模型是 Alexyu 的決定**，所以這次沒有自己換。

- **名字沒問題**：招牌上的店名照音譯翻出來了。把「要不要翻」交給類型而不是模型的感覺，對名字是對的。

## 暫停（2026-10-08，Alexyu 選 B）與重啟時先試的做法

實驗停在第六輪。參考同事的「影片切段送 Gemini」做法（另一個專案：只切需要的段落、轉成 720p 短片用 Gemini Files API 上傳、一次問好幾段、把角色表與劇情背景寫進提示、要求固定 JSON 格式），**重啟時先試**：

1. **粗看改用會看影片的模型**：Gemini 預設每秒看 1 格，「只出現兩三秒的字」不會再落在沒看到的空隙——這正是六輪裡每次漏題的原因。公開價格估算（未實測）：gemini-2.5-flash 一格約 258 token（低畫質 66）、每百萬 token US$0.30 → 一集 57 分鐘約 US$0.26（低畫質約 US$0.07）；聲音可以不送。
2. **細看仍用清楚的截圖**：一格 258 token 的畫質讀不到書名，所以只把「Gemini 說這幾秒有字」的格子截成大圖再讀（先粗後細不變，只是粗看那層換掉）。
3. **把這部片的名詞表放進提示**：招牌、字卡上的名字跟對白用同一套譯名（回應 Alexyu 對名字的疑慮）。
4. **注意上傳量**：轉成 720p 一集約 850MB，比現在的截圖（約 17MB）大很多；家用網路上傳慢，影片也會傳到 Google。可試更低的解析度，或只上傳有候選的段落。
5. **平台正在內建這件事**：Google 2026-09-01 推出讓模型自己決定看影片哪幾段的模式，宣稱 token 最多省 88%（[整理](https://rits.shanghai.nyu.edu/ai/gemini-agentic-video-understanding/)）。重啟時先看平台現成的做法，不要重做。

**API key 的原則（Alexyu 2026-10-08 提出的疑慮）**：Vido 現在最多要三把 AI key——Claude（翻譯）、OpenAI（聽聲音）、Gemini 或 Claude（檔名辨識，`AI_PROVIDER`）。新功能**不能讓「必填」的 key 變多**：

- 功能綁「能力」不綁廠商：同一個功能要能用使用者手上已經有的那把 key 跑（例如畫面字：有 Gemini 就看影片，只有 Claude 就用截圖）。
- 新的 key 只能讓功能「更便宜／更快」，不能是「沒有就不能用」。
- 長期方向（要不要「一把 key 全包」、要不要代管 key）是產品決定，交給 founder-pm／party mode。

## 文獻：比「先粗後細」更有效率的做法（2026-10-08 Alexyu 要求查）

| 做法 | 論文 | 跟我們的關係 |
|---|---|---|
| **偵測＋追蹤，每段字只辨識一次**：先用便宜的文字偵測器找出畫面上哪裡有字，跨格追蹤成「一串」，每串只挑畫質最好的一格去辨識 | YORO（[arXiv 1903.03299](https://arxiv.org/abs/1903.03299)，辨識快約 71 倍）；E²VTS（[arXiv 2206.02281](https://arxiv.org/pdf/2206.02281)：在滑動視窗裡挑最清楚的一格、丟掉沒字的格、裁掉沒字的區域） | 直接對症：我們漏題都是「沒挑到對的那格」。代價是要在 Docker 裡加一個**只找字在哪、不認字**的小模型（例如 DBNet，[arXiv 1911.08947](https://arxiv.org/pdf/1911.08947)）——跟 founder-pm「不自建 OCR」的界線有關，**要 Alexyu 決定** |
| **用便宜的圖文模型先打分，再分配解析度**：用 CLIP 類模型算每格「像不像有字卡／書／招牌」，分數高的給高解析度、低的給低解析度，總 token 固定 | Q-Frame（[arXiv 2506.22139](https://arxiv.org/html/2506.22139v2)，不用訓練）；AKS（[arXiv 2502.21271](https://arxiv.org/pdf/2502.21271)：同時顧「相關」與「覆蓋」） | 把現在最貴的「Opus 看 55 張拼圖」換成本機打分；同樣要加一個小模型 |
| **只在模型內部刪掉重複的畫面 token** | LongVU（[arXiv 2410.17434](https://arxiv.org/pdf/2410.17434)）、FastVID（[arXiv 2503.11187](https://arxiv.org/html/2503.11187v2)，刪 90% token、準確度維持 98%） | 要能改模型內部，**用 API 時做不到**；我們的感知雜湊去重是在模型外做類似的事 |

## 第七輪：比較找字模型（YORO 第一步，本機免費；2026-10-08 Alexyu 選 A）

Alexyu 改走 YORO：本機的小模型先找出「哪裡有字」，同一個位置連續幾格算同一段，每段只挑一張送 AI 讀。這一輪只比第一步「找字」，**沒有呼叫任何 API**，所以沒有預先寫及格線；比的是哪個找字模型值得進下一輪。

**做法**：兩部片整集每 2 秒截一張、寬 1280（See 1,709 張、Lioness 1,289 張）。每張跑找字模型，再用「框重疊超過 3 成」串成一段，允許中間漏一格。考題命中要**親眼看到裁下來的圖是那段字**才算，不是只看那幾秒有沒有框。程式在 `scripts/onscreen-detect/`。

| 找字模型 | 大小 | 考題（5 題） | 一集追出幾段（See／Lioness） | 每張多久：Mac／NAS（4 核） |
|---|---|---|---|---|
| PP-OCRv3 手機版 | 2.4MB | 4（漏《梅岡城故事》） | 655／461 | 0.05／0.20 秒 |
| PP-OCRv5 手機版 | 4.8MB | 3（漏《梅岡城故事》《一九八四》） | 689／563 | 0.03／0.12 秒 |
| PP-OCRv5 伺服器版 | 88MB | 4（漏《梅岡城故事》） | **361／254** | 0.22／1.45 秒 |
| DBNet++（PaddleOCR ResNet-50） | — | 只跑 12 張考題截圖：漏「學校辦公室」手機畫面、漏《梅岡城故事》 | 沒跑整集 | 1.1 秒／沒測 |

**看到的事**：

1. **《梅岡城故事》四個模型都找不到**：角色斜拿著書，封面是設計過的字型。其餘四題都有模型找得到。
2. **一閃即過的段不能丟**：《一九八四》和 CHARLIE MIKE'S 都只出現在 1 張截圖裡（鏡頭 2～3 秒）。原本想「只出現一張的多半是樹和雜訊，丟掉」——會把考題一起丟掉。所以段數不能靠這招砍。
3. **v5 伺服器版的段數最少**（誤判樹林、地面紋路最少），但在 NAS 上一張 1.45 秒，一集約 41 分鐘；v3／v5 手機版一集約 3～6 分鐘。
4. **DBNet++ 不划算**：考題截圖上比 v3 手機版漏得更多、慢 20 倍；而且轉不成 ONNX（`paddle2onnx` 報錯），要在 Docker 裡裝整套 PaddlePaddle。論文的 +2% 是街景照片的成績，搬到電影畫面沒有看到好處。

**NAS 怎麼裝（實測過）**：在 Unraid 上用 `python:3.12-slim` 跑 `onnxruntime`＋`opencv-python-headless`＋`rapidocr_onnxruntime==1.2.3`＋模型檔，不用網路、不用顯示卡，裝得起來也跑得動。⚠️ 要用 `opencv-python-headless`（一般版缺 `libxcb` 會起不來）。Vido 的映像檔是 Alpine＋純 Go（`CGO_ENABLED=0`），`onnxruntime` 官方只出 glibc 版，**不能直接塞進現在的 Vido 映像檔**；要嘛另開一個找字小容器讓 Vido 呼叫，要嘛 Vido 改用 Debian 底＋CGO。這是架構決定，做成正式功能前再決定。

**下一輪要量的**（要花 API 的錢，要先儲值、Alexyu 同意）：把每段挑出的那張裁成小圖、拼起來送 Opus 讀，量「5 題讀對幾題、多翻幾處背景字、一集多少錢」。《梅岡城故事》這類找字模型漏掉的，要另外補（例如保留原本的拼圖粗看當備援）。
